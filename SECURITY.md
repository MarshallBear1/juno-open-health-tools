# Security policy

## Supported versions

Security fixes are applied to the default branch and, when appropriate, included in the next tagged release. Older releases may not receive separate patches.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability.

Email `team@juno-chat.com` with the subject `Security report: Juno Open Health Tools`. Include:

- the affected component and version or commit;
- a concise description of the impact;
- reproducible steps or a minimal proof of concept using synthetic data;
- any suggested mitigation; and
- a safe way to contact you.

Never include real health information, patient records, credentials, API keys, tokens, or other personal data in a report. Redact logs and screenshots before sending them.

We aim to acknowledge a report within seven business days and provide an assessment or progress update within fourteen calendar days. Please allow time for investigation before public disclosure.

## Scope

This policy covers the code and artifacts in this repository, including the browser extension, MCP app, schemas, templates, packaging scripts, and published metadata. When reporting an issue in another Juno surface, identify that surface clearly so the report can be routed correctly.

Reports about medical advice quality, urgent symptoms, or personal care are not software vulnerability reports. The tools in this repository do not diagnose, prescribe, or replace professional care.
